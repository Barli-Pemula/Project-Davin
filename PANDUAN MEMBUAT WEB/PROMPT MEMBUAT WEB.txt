KONTEKS PRODUK
ARTANAYA adalah platform demonstrasi pembiayaan usaha pesisir melalui koperasi. Nelayan mengajukan modal dan melaporkan usaha; admin memverifikasi, meninjau, menerbitkan penawaran serta mengelola dana fiktif; investor mempelajari penawaran dan membeli unit simulasi. Semua identitas, saldo, efek, transaksi, MFA, liveness, fraud radar, dan hasil adalah fiktif. Jangan membuat klaim investasi atau pembayaran riil.

TUJUAN DESAIN
Buat pengalaman bahasa Indonesia yang kredibel dan mudah dipahami. Visual bertema pesisir, warna navy gelap, teal, putih/abu muda dan amber, foto pesisir nyata berlisensi dengan kredit, kartu rapi, tipografi tegas, progres dana yang terbaca, badge status berteks, dan rincian risiko yang jelas. Beranda berisi hero dan CTA, tiga ruang kerja, contoh proyek, alur, edukasi dan penjelasan Mode Demo. Portal responsif pada 360 px dan 1440 px, dengan sidebar desktop serta menu/navigasi bawah seluler. Semua alur inti dapat digunakan lewat keyboard; fokus jelas, input berlabel, gambar ber-alt, ikon tindakan bernama, dan skip link tersedia.

ALUR WAJIB
A. Registrasi investor/nelayan: nama 3-100, email valid unik, kata sandi minimal 10, password hash, KYC awal dan dompet. Login kredensial dengan batas percobaan; sesi delapan jam; logout.
B. KYC: unggah PDF/PNG/JPEG fiktif maksimal 2 MB, validasi signature dan MIME, data nama/lokasi, KUSUKA DEMO- untuk nelayan, kode MFA 123456 dan liveness simulasi. Admin setuju/perbaikan dengan alasan. Pembelian dan pengajuan memerlukan verifikasi.
C. Nelayan: form bertahap untuk judul, kategori, lokasi, koperasi aktif, modal kelipatan Rp50.000, rencana, lima sinyal 0-100 atau kosong. Simpan draf; unggah bukti rencana; ajukan; tampilkan skor, status, alasan revisi; izinkan revisi dan kirim ulang. Hanya pemilik yang boleh mengubah.
D. Skor: T/P/K/L/R berbobot 25/30/15/15/15. Normalisasi dari sinyal tersedia. R kosong saja dengan empat sinyal lain lengkap = Nelayan Baru dan skor final; sinyal wajib lain hilang = Perlu Verifikasi Tambahan; semua kosong = tanpa skor. 0 valid dan berbeda dari kosong. Kelas >=70 Tinggi, >=50 Sedang, <50 Perlu Pembinaan. Skor sementara atau <50 tidak boleh disetujui/diterbitkan.
E. Admin: tinjau proyek dengan alasan, buat penawaran atas nama koperasi, target sama dengan kebutuhan proyek dan kelipatan harga unit, periode 1-90 hari, risiko dan penggunaan dana, prospektus versi aktif, escrow dan akad. Publikasi harus memeriksa identitas, skor, koperasi, keanggotaan, dokumen dan periode.
F. Investor: katalog dengan pencarian judul/lokasi dan filter kategori; detail dengan koperasi, usaha, foto ilustrasi, skor, risiko, prospektus, penggunaan dana, progres, periode dan skenario hasil bukan jaminan. Top-up demo dan beli minimum Rp50.000, kelipatan harga unit, saldo cukup, tidak melebihi sisa target, penawaran aktif, persetujuan prospektus versi terbaru. Simulasi gagal tidak boleh mengubah dana.
G. Dana: pembelian memindahkan saldo investor ke escrow, target penuh menjadi SUKSES, admin melepas escrow ke koperasi sekali, kedua pihak menyetujui akad, admin menyetujui dan mencairkan tahap 1 (60%) lalu tahap 2 (40%) setelah laporan valid. Nelayan melihat saldo dan mutasi Dompetku.
H. Laporan: nelayan mengisi periode, progres, dana terpakai tidak melebihi dana cair, hasil usaha dan catatan; unggah bukti. Admin memvalidasi atau minta revisi. Rugi masuk tinjauan manual. Laba valid dibagi 60% koperasi/40% nelayan; 80% bagian koperasi untuk investor pro-rata, sisa rupiah deterministik. Laba nol membagikan nol. Pokok tidak dibayar kembali lewat distribusi laba.
I. Penawaran gagal: dalam mode demo admin dapat mengakhiri penawaran aktif yang belum penuh; refund setiap pesanan sekali ke investor. Jangan membuat saldo atau refund ganda.
J. Keamanan dan tata kelola: Self-Lock investor memblokir top-up/pembelian di server; membuka dengan kode demo 123456. Admin melihat alert radar demo, mengassign dan menyelesaikan dengan alasan. Admin menugaskan pendamping, dan hanya pendamping aktif dapat menulis catatan; nelayan dapat membacanya. Setiap keputusan dan mutasi diaudit.

KONTRAK TEKNIS
Gunakan TypeScript, Next.js App Router sesuai dokumentasi versi terpasang, React, Prisma, Zod dan autentikasi proyek. Periksa peran/kepemilikan/status di server. Semua nominal dana adalah BigInt rupiah bulat. Semua mutasi finansial dalam transaksi serializable dan jurnal debit-kredit seimbang. Kunci idempotensi per aktor+aksi+kunci dengan fingerprint payload; permintaan yang sama mengembalikan hasil lama dan payload berbeda ditolak. Batasi akses dokumen privat; gunakan no-store dan nosniff saat unduh. POST sensitif memeriksa Origin host sama. Jangan menulis secret atau identitas nyata ke log, hash atau UI. Penggunaan SQLite lokal dan PostgreSQL deployment harus mengikuti README serta migrasi yang benar.

KONTRAK DATABASE VERCEL YANG SUDAH ADA — WAJIB SAAT REBUILD
Tujuan utamanya adalah menggunakan kembali database PostgreSQL/branch yang saat ini terhubung ke Vercel Project ARTANAYA, beserta seluruh data lama, tanpa mengisi ulang URL atau secret ke source code. Deploy kode baru ke Vercel Project yang sama agar integrasi dan Environment Variables Production lama tetap dipakai. Jika repository diganti, ubah sumber deployment pada proyek Vercel yang ada. Jika terpaksa membuat Vercel Project baru, jelaskan bahwa database tidak tersambung otomatis dan integrasi/environment harus dipasang ke proyek baru melalui Vercel secara aman; jangan mengklaim “tanpa konfigurasi ulang”.

Pertahankan nama, scope dan nilai yang sudah ada di Vercel untuk DATABASE_URL, DATABASE_URL_UNPOOLED atau DIRECT_URL, AUTH_SECRET, AUTH_TRUST_HOST, DEMO_MODE, DEMO_PASSWORD serta NEXT_PUBLIC_HELP_WHATSAPP bila dipakai. Jangan menampilkan nilainya di log, PR, prompt, repo atau screenshot. DATABASE_URL runtime boleh pooled; migrasi harus memakai URL direct yang tidak ber-host -pooler. Jangan arahkan Preview atau tes mutasi ke Production. Pertahankan skema Prisma, model/enum, ID, nama tabel/kolom dan seluruh prisma/migrations lama. Setiap perubahan skema harus berupa migrasi maju yang kompatibel dan diuji pada staging/salinan data. Jangan menjalankan prisma db push, prisma migrate reset, truncate, drop, atau seed destruktif terhadap Production.

Pertahankan proses build yang aman: scripts/build-demo.mjs sekarang hanya menjalankan Prisma generate dan Next build. Migrasi PostgreSQL memakai scripts/deploy-migrations.mjs melalui npm run db:deploy atau db:migrate dan tidak menjalankan seed. scripts/setup-demo.mjs hanya untuk SQLite lokal atau bootstrap PostgreSQL baru dengan DEMO_BOOTSTRAP=true. Seed tetap meng-update passwordHash akun demo bila dijalankan; jangan jalankan pada database lama. Ambil backup/snapshot provider sebelum migrasi, cek status migrasi dan jumlah data sebelum/sesudah, lalu verifikasi login, proyek, penawaran, pesanan, dompet, jurnal, audit dan akses dokumen lama. Bila ada drift atau kegagalan koneksi, hentikan rollout; jangan mengarahkan aplikasi ke database kosong baru. Dokumentasikan jalur rollback yang memperhitungkan perubahan skema.
